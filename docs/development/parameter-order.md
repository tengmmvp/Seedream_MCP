## O1 组序基准

**意图**：为全部生成类工具提供唯一规范序，消除各处自定序导致的漂移。

**规则**：生成类工具（文生图 `text_to_image`、图文生图 `image_to_image`、多图融合 `multi_image_fusion`、组图输出 `sequential_generation`、图层拆分 `layer_decompose`；新增生成语义的工具自动入类）的参数按七组排列，组序固定为 G1→G2→G3→G4→G5→G6→G7，对应一次调用的心智过程：要什么 → 工具规则是什么 → 怎么生成 → 产出什么格式 → 怎么送达 → 怎么执行 → 存到哪里。

| 组  | 组名     | 回答的问题     | 域   |
| --- | -------- | -------------- | ---- |
| G1  | 内容     | 要什么         | 官方 |
| G2  | 特有配置 | 工具规则是什么 | 官方 |
| G3  | 生成控制 | 怎么生成       | 官方 |
| G4  | 产出格式 | 产出什么格式   | 官方 |
| G5  | 送达方式 | 怎么送达       | 官方 |
| G6  | 执行编排 | 怎么执行       | 项目 |
| G7  | 存储     | 存到哪里       | 项目 |

组序受两条轴同时约束：

- **依赖轴**：后组依赖前组。内容先于一切；特有配置限定调用模式；生成控制作用于内容；产出格式包装结果；送达传输结果；编排调度动作；存储处理落盘。反方向放置不成立。
- **归属轴**：G1–G5 仅允许官方 API 参数；G6–G7 仅允许项目自有参数，不进官方请求体。两域禁止互插。

组序在两条轴的论证被推翻前固定；对组序的异议以两轴论证裁决，修订组表时同步附录 A、锁序测试断言与已登记派生场合并记变更记录，增设新组走同一通道。

**例外**：`browse_images` 不属生成类，见 O6；`get_model_info` 无参数，不适用。嵌套 options（如 `sequential_image_generation_options`）的子字段序不属本规范管辖，随官方文档序维护。

## O2 组内顺序

**意图**：同一组内的多个参数有确定的相对位置，不按加入时间排列。

**规则**：组内定位按以下原则，冲突时按列出顺序优先：

1. 总量先于粒度（如 `request_count` 先于 `parallelism`）
2. 开关先于其所辖取值（如 `auto_save` 先于 `save_path` 与 `custom_name`；取值类目为可增补清单，当前为位置、命名两类）
3. 指令先于其修饰配置，先于素材输入（G1：`prompt` → `optimize_prompt_options` → `image`）
4. 数据形态先于时序形态（如 `response_format` 先于 `stream`）
5. 使用频率高者靠前（兜底原则，前四条不适用时使用；如 `size` 先于 `watermark`）

## O3 新参数归位

**意图**：防止新参数一律尾部追加，组序随参数增长失效。

**规则**：参数的位置由它回答的问题决定，不由加入时间决定。新参数禁止一律追加在参数列表尾部，须按三步归位：

1. 判域定组，先命中先归属：
   - 官方 API 参数——仅单一工具暴露的模式限定配置进 G2（模式限定配置指选择或配置该工具特有的调用模式、决定做什么类型的事；调节单次生成强度、质量或数量的参数不属此类，入 G3）；内容参数（指令、指令修饰、素材，不论是否跨工具共享）进 G1；其余按顺序判定：调节生成过程的进 G3，决定产出文件形态的进 G4，决定传输形态的进 G5
   - 项目自有参数——影响请求执行方式的进 G6，涉及文件落盘的进 G7
2. 按 O2 在组内定位
3. 仍无法判定时，在变更记录登记裁决理由后，归位于语义最接近的组；裁决确立新的组内定位原则时，增补 O2 条目并在变更记录交叉引用

归位后须按 `sync-points.md` 的顺序落点清单同步全部落点，并把新参数登记进附录 A 相应组行（新工具并更新缺席工具列）。整改收口前，新参数以附录 A 规范序为锚落位：组归属与组内关系以规范序为准，不以周边参数的现状位置为准；既有差异不因加参数收敛或扩大，锁序测试断言与附录 B 已登记派生场合按新现状序随动。

**机器执行**：锁序测试（见 O7）。

**参见**：O5（官方新增参数的归位方式）

## O4 顺序派生场合

**意图**：防止各派生场合自行设计顺序，造成同一输入多套呈现序并存。

**规则**：派生场合指呈现工具参数全集或子集的场合；场合内输入派生参数按现状序（输入模型当前字段序）排列，非输入的包装字段顺序不属本规范管辖。按名绑定、顺序无语义的构造调用（kwargs、夹具字典）非呈现面，不属派生场合；模拟工具调用的参数全集载荷与共享构造工厂的全字段罗列属呈现面。未登记的场合按阶梯推断：

1. 能投影输入参数的场合：直接跟随
2. 不能投影但 O1 两轴适用的场合：按轴定组、按 O2 定组内位置
3. 两轴不适用的场合（如错误消息、日志的字段序）：按 O6 先例另立基准条款登记

发现新场合后增补至附录 B。

**例外**：按 UI 分区或使用主题组织的呈现（`webapp` 表单、`SKILL.md` 参数规则与 `skills` 目录参考文件为其例：均呈现工具参数子集、按分区或使用主题折叠组织），分区与主题序不受组序约束；同一分区或主题内多参数的相对先后遵循现状序。

**机器执行**：`GenerationExecutionContext` 参数序由 `tests/tools/test_generation_context.py` 守护；`structuredContent` 回显仅与输出模型声明对账（字段集与取值实例化校验，`tests/tools/test_output_schema_consistency.py`），`README` bullet 仅参数集对账（`tests/contracts/test_readme_code_parity.py`，三语序列互等由 `tests/contracts/test_docs_consistency.py` 锁定）；`structuredContent` 回显与 `README` bullet 的顺序暂无机器守护。

**参见**：O6（两轴不适用场合的先例）、附录 B（已登记场合清单）

## O5 官方参数归位

**意图**：官方文档的参数排列不构成本项目的顺序依据，防止照抄叙述序。

**规则**：官方文档排列是叙述序，仅作参照；其合理局部（如内容参数相邻、模式配置紧跟参考图）与 O1 吻合的，自然继承。官方新增参数须按 O3 归位插入，禁止按官方文档位置插入。值由部署配置或系统派生、或属调用模式与工具选择本身的官方参数，不进入工具参数、不参与组序；现行此类参数为 `model`、`safety_identifier`、`sequential_image_generation`（组图模式）与 `layer_decomposition`（图层拆分开关），新增同类参数按同一判据判定后增补本条列举。

**参见**：O1 例外（嵌套 options 子字段序随官方文档序维护）

## O6 浏览工具顺序

**意图**：`browse_images` 无生成语义，单独定义其规范序。

**规则**：按由粗到细排列：范围（`directory`）→ 遍历方式（`recursive`、`max_depth`）→ 分页（`limit`、`offset`）→ 过滤（`format_filter`）→ 展示（`show_details`）。新参数按由粗到细原则归入最粗适切的既有段，段内按 O2 定位；无适切段或位置存疑时，按 O3 步骤 3 同款裁决登记，裁决认定无适切段时增补段序并在变更记录交叉引用。

**机器执行**：锁序测试（见 O7；`test_browse_images_parameter_order` 逐字锁定本条段序）。

## O7 机器守护与冲突裁决

**意图**：顺序约束由测试执行，分歧有唯一裁决依据。

**规则**：锁序测试（`tests/tools/test_tool_parameter_order.py`，含逐工具硬编码的参数序断言，承载现状序）锁定平铺签名（`server/_registration.py` 中工具注册的平铺参数签名）与输入模型的参数名与顺序全等；重排或加参数时，须在输入模型、平铺签名与锁序测试断言三处同步，漏任一处即测试失败。代码与本规范冲突时，以本规范为准修正代码。

## O8 差异清点与整改

**意图**：现状序与规范序的差异可清点、可整改、可收口。

**规则**：附录 A 登记规范序，现状序由锁序测试承载，二者差异均为待整改项；附录 B 已登记派生场合的输入派生参数序与规范序的差异同为待整改项（分区与主题序除外，见 O4 例外）。差异清点分两路：

- 现状序差异：以附录 A 逐组对照锁序测试的硬编码序
- 派生场合差异：以规范序核对登记场合的输入派生参数序

整改须输入模型、平铺签名、锁序测试断言与已登记派生场合均重排为规范序；全部完成后，锁序测试即附录 A 的机器执行（联动经三处同步的程序规则间接成立，单独修订附录 A 须同步锁序测试断言）。输入模型经 mixin 继承列表的逆序实现参数序：特有配置 mixin 在继承列表中须列于尺寸/水印 mixin 之后、参考图 mixin 之前，如此排列即得「参考图 → 特有配置 → 尺寸/水印」的规范序 G1–G3 段。

**机器执行**：锁序测试（见 O7）。

## 附录 A 生成类工具规范序

> 本附录登记规范序（目标态）；现状序、差异清点口径与整改后语义见 O8。

| 组  | 参数                                                                  | 缺席工具                               |
| --- | --------------------------------------------------------------------- | -------------------------------------- |
| G1  | `prompt` → `optimize_prompt_options` → `image`                        | `image`：文生图                        |
| G2  | `layer_decomposition_options` / `sequential_image_generation_options` | 无 G2 参数：文生图、图文生图、多图融合 |
| G3  | `size` → `background` → `watermark` → `tools`                         | `background`：图层拆分                 |
| G4  | `output_format`                                                       | —                                      |
| G5  | `response_format` → `stream`                                          | —                                      |
| G6  | `request_count` → `parallelism`                                       | —                                      |
| G7  | `auto_save` → `save_path` → `custom_name`                             | —                                      |

G2 两参数每工具至多一个。`browse_images` 见 O6；`get_model_info` 无参数。`background` 在图层拆分缺席系官方明文相斥（该场景禁传，传入报错）；组图输出的 `background` 由能力表运行时门控，模型不支持时报能力错误。

## 附录 B 派生场合登记

> 随代码与界面演进漂移的注册名单；新场合按 O4 阶梯推断后增补至本附录。

- `GenerationInputParams` 协议成员序（五个输入模型共享字段的投影）
- `GenerationExecutionContext` 参数序（跨工具合并的输入派生参数序）
- `_BrowseRequestState` 参数序（`browse_images` 输入参数子集的请求状态快照，随现状序）
- `client` 生成方法签名参数序（`client/_api.py`，落点见 `sync-points.md`；除首参 `prompt` 可位置传入外全部 keyword-only，位置错绑即刻 TypeError）
- 公共参数校验通道参数序（`utils/core/validators.py` 与 `client/_api.py`，四处联动，落点见 `sync-points.md`）
- validators 多参校验与合成函数签名序（`utils/core/validators.py`，输入派生参数随规范投影，非输入包装字段位置不管辖；落点见 `sync-points.md`）
- `structuredContent` 回显参数序（`tools/outputs/__init__.py` 输出模型字段序与 `tools/pipeline/results.py` 装配清单序）
- 生成与浏览开始日志字段序（`tools/handlers/_metadata.py` 与 `client/_api.py` 各生成方法的开始日志随输入派生参数序；`tools/handlers/browse_images.py` 的浏览开始日志随 O6 段序）
- 校验错误消息参数提及序（`utils/core/validators.py`，随规范投影；参数描述文本以被描述参数为主体先行，不属本条）
- 参数描述散文的参数提及序（`utils/core/validators.py` docstring、`tools/schemas.py` 字段描述常量、`tools/pipeline/context.py` 的 `build_generation_context` docstring）：主体（被描述参数）先行，其余提及循规范序；按语义分句组织的散文分句内循规范序、分句组织不循组序
- `README` 三语参数 bullet 与调用示例 JSON 载荷
- `webapp` 表单与前端参数：表单随 UI 分区折叠（见 O4 例外）；前端提交载荷（`webapp/static/js/generate.js` 的 `buildRequestBody` 平铺全字段构造，属模拟工具调用的参数全集载荷呈现面）键序随现状序
- `SKILL.md` 参数规则、工具速查必需参数列与 `skills` 目录参考文件（见 O4 例外；参考文件的叙事散文散点提及不登记，单句罗列与同主题/步骤内多参数相对先后循现状序）
- 测试模拟工具调用的参数载荷（`tests/server/test_tool_call_assembly.py` 全字段载荷与 `tests/e2e/test_streamable_http_e2e.py` 线缆级子集载荷）
- 共享构造工厂全字段罗列（`tests/_lib/generation_fixtures.py` 的 `make_generation_context` defaults）
